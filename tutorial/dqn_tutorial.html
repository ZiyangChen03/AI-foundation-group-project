Deep Q-Networks for Battleship

A from-zero tutorial: how DQN works, why we designed ours the way we did, and how the code in battleship/dqn/ implements it.

0How to read this

The tutorial has three parts. Read them in order: each one uses ideas from the one before.

  1. How DQN works. From "what is a reward" to the full DQN algorithm. No code.
  2. Our design. Why each choice in our Battleship DQN was made, and what it buys us.

1The game as a learning problem

Reinforcement learning (RL) is learning by trial and error: an agent takes actions in an environment, gets rewards, and gradually learns which actions lead to the most reward.

RL wordIn Battleship
AgentThe player who fires (our program).
EnvironmentThe board with the hidden ships. It answers each shot.
State sThe visible board plus the list of ships still afloat. The agent never sees the hidden layout.
Action aOne of the cells not yet fired at.
Reward r−1 for every shot, hit or miss.
EpisodeOne whole game, from the empty board to the last ship sunk.
PolicyThe agent's rule for choosing a shot in each state. Learning = improving the policy.
Why −1 per shot? We want to sink the fleet in as few shots as possible. If every shot costs −1, the total reward of a game is exactly −(number of shots), so maximizing reward = minimizing shots. A reward like "+1 per hit" would not work: every game has exactly 17 ship cells, so every strategy would total +17 and the agent couldn't tell good play from bad.
Check yourself: a game took 47 shots. What was its total reward? −47. One −1 per shot.

2Return and the discount γ

The return is the total reward from now until the game ends. With a discount factor γ (gamma):

return = r₁ + γ·r₂ + γ²·r₃ + …r₁ is the reward of this shot, r₂ of the next one, and so on.

γ says how much a reward later is worth compared with a reward now:

  • γ = 1: every shot counts the same. Return = −(shots left).
  • γ = 0.9: a shot 10 moves away counts only 0.9¹⁰ ≈ 0.35 as much.

Rule of thumb: γ "looks ahead" about 1 / (1 − γ) steps. γ = 0.9 sees ~10 shots, γ = 0.99 sees ~100.

γValue of a 45-shot gameValue of a 60-shot gameCan it tell them apart?
1.0−45.0−60.0Yes, clearly
0.99−36.4−45.3Yes
0.9−9.91−9.98Barely: this would wreck learning
Our choice: γ = 1 A Battleship game always ends (at most 100 shots), so the total can't blow up, and our goal really is "every shot costs the same". γ = 1 matches the goal exactly.
Common confusion γ does not make the agent act randomly. That's ε (section 5). γ only decides how far ahead the agent cares.
Check yourself: why would γ = 0.9 be bad for 10×10 Battleship? It only looks ~10 shots ahead, so a game of 45 shots and one of 60 look almost equally bad (−9.91 vs −9.98). The agent would have no reason to finish efficiently.

3The Q-value

Q(s, a) = expected return if you fire at a in state s, and play as well as possible afterwards

With reward −1 per shot and γ = 1: Q(s, a) = −(expected number of shots still needed, counting this one). So Q is always negative, and closer to 0 is better.

If we knew Q, playing would be trivial: fire at argmaxa Q(s, a), the cell with the largest Q.

Worked example: a 1×4 strip

One ship of length 2 is hidden on a strip of 4 cells. It can be at {0,1}, {1,2} or {2,3}, each with probability ⅓.

0123

Fire at cell 1:

  • Hit with probability ⅔ (ship at {0,1} or {1,2}). Then try cell 0 or 2: half the time it sinks the ship (1 more shot), half the time you need 2. Average 1.5 more shots.
  • Miss with probability ⅓ (ship must be {2,3}). Then 2 more shots.
Q(start, 1) = −1 + ⅔·(−1.5) + ⅓·(−2) = −2.67

Fire at cell 0:

  • Hit with probability ⅓ (ship at {0,1}). Then cell 1 is certain: 1 more shot.
  • Miss with probability ⅔. Cell 2 is now certain to be a hit, then one or two more: average 2.5 more shots.
Q(start, 0) = −1 + ⅓·(−1) + ⅔·(−2.5) = −3.00

−2.67 > −3.00, so the best first shot is the middle. That matches intuition: cell 1 belongs to more possible ship positions.

Check yourself: after a hit at cell 1, what is Q of firing at cell 3? The ship is at {0,1} or {1,2}, so cell 3 is a certain miss. You waste a shot and are back in the same situation: Q = −1 + (−1.5) = −2.5, worse than firing at 0 or 2 (−1.5).

4The Bellman equation

Look at how we computed Q above: "this shot's reward, plus the value of the best play afterwards". Written generally, that's the Bellman equation:

Q(s, a) = Σs′ P(s′ | s, a) · [ r + γ · maxa′ Q(s′, a′) ]For every possible outcome s′: its probability × (reward now + discounted value of the best next shot). Then add them up.

Piece by piece:

  • Σs′ P(s′ | s, a) · […]: average over the outcomes (hit or miss), weighted by how likely each is.
  • r: this shot's reward (−1).
  • maxa′ Q(s′, a′): in the next state, assume we'll take the best shot.
  • When the game is over, there are no more shots: max Q = 0.

In our game r = −1 whatever happens, so the reward comes out of the sum, and with γ = 1 it simplifies to:

Q(s, a) = −1 + 𝔼[ maxa′ Q(s′, a′) ]
The one idea to remember The value of a shot = its cost now + the value of the best shot after it. Everything in Q-learning and DQN is a way of making this equation true.
Check yourself: why can we pull r out of the sum here? Because r = −1 for every outcome. Σ P(s′)·(−1) = −1·Σ P(s′) = −1, since the probabilities add up to 1.

5Q-learning

To compute Q with the Bellman equation, we needed the probabilities P (the ⅔ and ⅓). A learning agent doesn't know them. Q-learning learns Q from experience instead: play, see what happened, nudge Q toward it.

After each shot you see one transition: (s, a, r, s′).

target  y = r + γ · maxa′ Q(s′, a′)
error   δ = y − Q(s, a)
update  Q(s, a) ← Q(s, a) + α · δ
  • y ("target"): the Bellman right-hand side, but using the one outcome that actually happened instead of averaging over all outcomes.
  • δ ("TD error"; TD = temporal difference): how wrong our guess was.
  • α (learning rate, e.g. 0.1): how far we move toward the target. Small = slow but steady.
Why this works without P If a shot hits ⅔ of the time, then about ⅔ of the targets you see are "hit" targets. Q becomes a running average of the targets, and that average converges to the same Σ P·(…) we computed by hand. Sampling replaces the probabilities.

ε-greedy exploration

If the agent always picks argmax Q, it never tries shots it currently thinks are bad, and never discovers they might be good. So:

with probability ε:  fire at a random legal cell     ← explore
otherwise:           fire at argmax Q(s, a)          ← exploit

ε starts high (e.g. 1.0: fully random) and shrinks during training (e.g. to 0.02). When we measure the agent, ε = 0.

Check yourself: Q(s, a) = −0.5, and a shot gives target y = −1. With α = 0.5, what is the new Q? δ = −1 − (−0.5) = −0.5. New Q = −0.5 + 0.5·(−0.5) = −0.75.

6Why a table fails

Plain Q-learning stores one number Q(s, a) per state and action: a Q-table. Our teammates tried this:

AttemptState used as table keyResult (4×4)What happened
PR #14The visible board13.9 shots (random: 14.1)3.5 million states after 1M games, about 4 updates each. 40% of test moves met a never-seen state.
PR #15The exact belief (set of possible layouts)8.97 shotsEquivalent boards share one entry: 320k states. Works, but needs every layout listed.

On 10×10, both break:

  • There are about 4¹⁰⁰ possible boards. A table would never see the same board twice.
  • There are 30,093,975,536 ship layouts. One belief alone would be a 3.8 GB bitmask.
The core problem A table can't generalize. Learning "hit next to unknown cells, so fire beside it" in one corner teaches it nothing about the same pattern elsewhere. We need a function that takes any board and gives sensible Q-values, including boards it never saw. That's what a neural network does.

7Neural networks in 15 minutes

A neural network is a function with many adjustable numbers (weights, written θ). You feed it numbers, it outputs numbers. Training means adjusting θ until the outputs are what we want.

One neuron

output = ReLU( w₁·x₁ + w₂·x₂ + … + b )x = inputs, w = weights, b = bias (an extra adjustable number). ReLU(z) = max(0, z).
  • The weighted sum lets the neuron decide how much each input matters.
  • ReLU ("rectified linear unit") sets negative values to 0. Without it, stacking neurons would collapse into a single weighted sum; with it, the network can represent complicated, bendy functions.

Layers

Neurons are arranged in layers. Each layer's outputs are the next layer's inputs. Early layers find simple patterns; later layers combine them into complex ones.

Loss

To train, we need a number that says how wrong the network is: the loss L(θ). The simplest is squared error:

L = (prediction − target)²

It's 0 when the prediction is perfect and grows quickly as the prediction gets worse. Training = making L small.

8Gradient descent, slowly

How do we change θ to make the loss smaller? Imagine the loss as a hilly landscape, where your position is θ and the height is L. You want to walk downhill.

  • The gradient ∇L tells you which direction is uphill, and how steep it is.
  • Gradient descent: take a small step the opposite way.
θ ← θ − η · ∇L(θ)η ("eta", the learning rate, lr in code) = the step size.

A tiny example with one number

Suppose the "network" is just one number q (a prediction of Q), and the target is y = −3.

L(q) = (q − y)²   ⇒   slope dL/dq = 2·(q − y)

Start at q = 0 with η = 0.25:

Stepqslope 2(q − y)new q = q − 0.25·slopeloss

Each step halves the distance to −3. That's gradient descent.

Surprise: this is the Q-learning update q ← q − η·2(q − y) = q + 2η·(y − q). Compare with Q ← Q + α·(y − Q). They're the same, with α = 2η. Tabular Q-learning is gradient descent on a squared error, one table entry at a time. DQN does the same thing, but on a network's weights.

With millions of weights

A real network has thousands of weights. You can't work out slopes by hand, but PyTorch does it automatically (this is called backpropagation): you compute the loss, call loss.backward(), and PyTorch fills in the slope for every weight. Then an optimizer takes the step.

  • Batch: instead of one example per step, we average the loss over many (e.g. 256). The step direction is then less noisy.
  • Adam: a popular optimizer. Plain gradient descent with a smarter, per-weight step size. You don't need its details.
loss = ((prediction - target) ** 2).mean()   # how wrong, averaged over the batch
optimizer.zero_grad()                         # clear old slopes
loss.backward()                               # compute the slope for every weight
optimizer.step()                              # move every weight a little downhill
Check yourself: what happens if η is far too large? Steps overshoot the bottom. With η = 1 in the example, q jumps from 0 to −6, then back to 0, forever. With even larger η it diverges. Too small, and learning takes forever.

9From table to network: DQN

DQN = Deep Q-Network (DeepMind, 2015, the Atari paper). Replace the Q-table with a neural network:

Q(s, a) ≈ Qθ(s)[a]The network takes the board s and outputs one Q-value per cell; [a] picks out the value for cell a.

Then train it by gradient descent, using the Q-learning target as the "correct answer":

L(θ) = ( Qθ(s)[a] − y )²,    y = r + γ · maxa′ Q(s′)[a′]

Because similar boards produce similar network outputs, learning from one board also improves the predictions for boards the agent has never seen. That's exactly the generalization the table lacked.

The catch The target y contains Q itself. When we update θ, the target moves too. It's like chasing your own shadow. On top of that, consecutive shots in one game are very similar, so the network over-fits to the current game. Plain "Q-learning + network" is famously unstable. Section 10 is about the fixes.

10The tricks that make DQN stable

Trick 1: experience replay

Store every transition (s, a, r, s′, done) in a big replay buffer. To train, pick a random batch from it.

  • Breaks correlation: a batch mixes shots from many different games, not 256 shots in a row from the same board.
  • Reuses data: each experience is trained on several times (our replay ratio, 8).

Trick 2: target network

Keep a second, frozen copy of the network, with weights θ⁻, and compute targets with it:

y = r + γ · maxa′ Qθ⁻(s′)[a′]

Every N training steps (we use 1,000), copy θ into θ⁻. Between copies, the target stays still, so the online network has a fixed goal to move toward.

Trick 3: Double DQN

Taking the max over 100 noisy estimates picks whichever happens to be too high. So targets are biased upward ("overestimation"). Double DQN splits the job:

a* = argmaxa′ Qθ(s′)[a′]  (online network chooses)
y = r + γ · Qθ⁻(s′)[a*]  (target network evaluates)

One network's lucky overestimate is unlikely to be the other's too.

Trick 4: Huber loss

Squared error punishes large errors very hard: an error of 20 counts 400. Early in training, errors of 20+ shots are common, so a few bad examples can yank the weights around. Huber loss is squared for small errors (< 1) and grows only linearly for large ones. PyTorch calls it smooth_l1_loss.

Trick 5: action masking

Already-fired cells are illegal. We set their Q to −∞ before choosing a shot and before taking the max in the target. The agent can never waste a shot, and illegal cells never pollute the targets.

Check yourself: what problem does each of tricks 1 and 2 solve? Replay: consecutive shots are correlated, and data would be used once. Target network: the target would move every time we update, so the network chases itself.

11The full algorithm

initialize network Q_θ randomly;  target network θ⁻ ← θ;  empty replay buffer

repeat for many games:
    look at the board s
    with probability ε: a ← random legal cell
    otherwise:          a ← argmax over legal cells of Q_θ(s)
    fire at a; observe r = −1, the next board s′, and whether the game ended (done)
    store (s, a, r, s′, done) in the replay buffer

    sample a random batch of transitions from the buffer
    for each:  y = r                                        if done
               y = r + γ · Q_θ⁻(s′)[ argmax_a′ Q_θ(s′)[a′] ]  otherwise   (Double DQN)
    loss = Huber( Q_θ(s)[a] − y ), averaged over the batch
    one gradient-descent step on θ

    every 1,000 steps: θ⁻ ← θ
    slowly decrease ε

That's all of DQN. Everything in Part 2 is about what s looks like, what network to use, and which numbers to pick, for Battleship.

12The question we ask

Research question Can a model-free learner (one that is never told the rules of ship placement) learn to play 10×10 Battleship as well as the best hand-written strategy, probability density, and can it beat it?

What we compare against, on 10×10:

StrategyMean shotsHow it works
Random~95Fire anywhere.
Hunt-target with parity~62–65Fire on a checkerboard until a hit, then fire at its neighbours.
Probability density44.65 ± 0.4Try every position of every remaining ship, count how many cover each cell, fire at the highest count. (Measured: 2,000 boards.)
Best published DQN we found~52A hobby project; no peer-reviewed DQN benchmark exists.

Probability density is strong but has three known flaws: it counts each ship separately (it ignores that ships can't overlap), its "follow up on hits" rule uses a hand-picked weight of 50, and it's greedy (it never asks which shot makes the next shots cheaper). DQN's Q-value is "shots still needed", so in principle it can learn to look ahead.

13What the network sees

A network needs numbers, so we turn the board into a stack of 10×10 grids called planes (or channels, like the red/green/blue channels of an image). Each plane holds 0s and 1s, or small counts:

PlaneValue at each cellWhy
hit1 if hit (ship not yet sunk)Where to follow up
miss1 if missWhere ships aren't
sunk1 if part of a sunk shipFinished; ships can't be here
on-boardalways 1Explained below
ships of length 1…5 (5 planes)How many ships of that length are afloat, the same number everywhereWhich ships are left changes where they fit
density (variants B and C only)Probability-density score, scaled so the best cell is 1A strong hint

Unknown cells are simply 0 in the hit, miss and sunk planes.

Is this a valid state? The game hides the layout, so it's a POMDP (partially observable). But observations are exact (no noise), so the board plus the remaining ships contains everything the agent knows: the exact belief can be computed from it. That makes it a proper Markov state: nothing else about the past matters. The density plane is computed from the board too, so it adds no new information, just a pre-computed, useful feature.
Why an "on-board" plane of 1s? Convolutions (next section) pad the board's edge with zeros. Without this plane, "off the board" and "unknown cell" would both look like all-zeros. With it, the network sees exactly where the edge is, which matters: ships can't stick out.

14Why a convolutional network

A convolution slides a small grid of weights (a filter, here 3×3) over the board. At each cell it computes a weighted sum of that cell and its 8 neighbours. One filter = one pattern detector.

For example, a filter that weights "hit on the left" positively and "this cell is unknown" positively lights up wherever a hit has an unknown cell to its right: a good place to fire.

ox??

The 3×3 filter centred on the third cell sees "hit to my left, I'm unknown": a strong signal.

  • Weight sharing: the same filter is used at every cell. A pattern learned in one corner works everywhere. That's the generalization a table lacks, and it keeps the network small (our 32-channel network has about 35,000 weights).
  • Receptive field: one 3×3 layer sees 1 cell in each direction. Stacking 4 layers sees 4 cells away, a 9×9 window. That's enough to see a whole 5-long carrier passing through any cell. That's why we use 4 layers.
  • Channels: each layer has 32 filters, so it produces 32 planes of pattern-detections for the next layer.
  • No fully connected layer: the output is computed per cell by a 1×1 convolution, so the network keeps the grid structure. A project that used a plain fully connected network stalled at 85–99 shots.

15The dueling head

Here's a subtle problem. Q(s, a) ≈ −(shots still needed). The "shots still needed" part depends on the whole board (how much is left to find), but a 9×9 local window can't see the whole board. Meanwhile, which cell is best is mostly local.

So we split Q into two parts (the dueling architecture, Wang et al. 2016):

Q(s, a) = V(s) + A(s, a) − meanlegal a A(s, a)V = value of the board (one number, from the whole board). A = advantage of each cell (how much better or worse than average).
  • V(s) is computed from global pooling: the average and the maximum of each of the 32 feature planes over the whole board, then a small fully connected layer. It sees everything.
  • A(s, a) comes from a 1×1 convolution: local, one value per cell.
  • Subtracting the mean of A makes the split unique (otherwise V could be +5 and every A −5).
Why it helps The choice of cell (argmax) depends only on A, which is local, as it should be. The level of Q, needed for good targets y, comes from V, which is global. Each part does the job it's suited for.

16Three variants: A, B, C

To learn what helps, we train three versions and compare them. Changing one thing at a time like this is called an ablation.

VariantInputsQQuestion it answers
A. Board only (main)hit, miss, sunk, on-board, shipsNetworkCan pure DQN learn Battleship from scratch?
B. Density inputA + density planeNetworkDoes the density help as a feature?
C. ResidualA + density planec · density + networkDoes it help as a starting policy? Can learning beat the expert?

How the residual variant works

Q(s, a) = c · density(s, a) + networkθ(s)[a]

The last layer of the advantage part starts at all zeros, so at the very start A = 0 and the agent fires at the highest density: it plays exactly like probability density (~44.6 shots) from game 1, instead of randomly (~95). DQN then only has to learn a correction. The density term is fixed, so the only learned part is still trained with the ordinary DQN loss: it's still DQN.

Honest expectations On 4×4, where the exact optimum is known, greedy play is only 1.9% above optimal. If 10×10 is similar, there's less than a shot to gain over density. So for C, "no significant gain" is a likely, and still meaningful, result.

17Making it fast

Playing one game at a time in Python and training a batch every 4 shots would cost about 1 ms per shot: 100k games ≈ 80 minutes. We cut that about 10× with three changes:

  1. 256 games at once. The boards are stored as tensors (PyTorch arrays), and one network pass chooses 256 shots. Measured: a batched forward pass costs 1–3.5 µs per board instead of ~430 µs.
  2. Replay ratio 8. Each stored shot is trained on 8 times on average, the standard Atari DQN setting (my first plan used 32).
  3. 32 channels, not 64. Measured: 1.7× cheaper per training sample.

Result: about 140 games per second on 10×10, so 100k games in ~12–15 minutes.

Device split The games and the density map run on the CPU. The network trains on the M3's GPU (MPS, "Metal Performance Shaders", Apple's GPU backend for PyTorch).

20vec_env.py: the games

Each board is a row of 100 small integers: 0 unknown, 1 miss, 2 hit, 3 sunk. With 256 games, board is a 256×100 tensor.

battleship/dqn/vec_env.py

self.board   = torch.zeros(n, cells, dtype=torch.int8)        # what the agent sees
self.ship_at = torch.full((n, cells), -1, dtype=torch.long)   # hidden: which ship is at each cell (-1 = none)
self.left    = torch.zeros(n, ships, dtype=torch.long)        # hidden: cells still afloat per ship

ship_at and left are the hidden layout. The agent's network never receives them: only board and remaining() are encoded.

Firing one shot in every game

def step(self, actions, active=None):
    rows  = torch.arange(self.n) if active is None else active.nonzero().flatten()
    cells = actions[rows]
    ship  = self.ship_at[rows, cells]        # which ship (if any) is at each fired cell
    hit   = ship >= 0
    self.board[rows, cells] = torch.where(hit, HIT, MISS)
    self.left[rows[hit], ship[hit]] -= 1     # one fewer cell afloat
    sunk = self.left[rows[hit], ship[hit]] == 0
    ...                                      # if sunk: mark that ship's cells SUNK
    return self.done                         # True where every ship is sunk

This does the same thing as the original BattleshipEnv.step, but for all 256 games in a handful of tensor operations, with no Python loop over games.

The density map with convolutions

Probability density asks, for each ship length L: "where can a ship of length L fit?" A position fits if none of its L cells is a miss or sunk. That's a sliding window, which is exactly what a convolution with a kernel of ones computes:

kernel = torch.ones(1, 1, 1, L)                     # a 1×L window (horizontal ships)
fits   = F.conv2d(blocked, kernel) == 0             # no blocked cell inside the window
weight = fits * 50 ** F.conv2d(hits, kernel) * count  # 50^k for k open hits; × ships of this length
score += F.conv_transpose2d(weight, kernel)         # spread each position's weight back onto its L cells

conv_transpose2d does the reverse of the sliding window: each valid position adds its weight to all the cells it covers. The same is repeated with an L×1 kernel for vertical ships. Finally, already-fired cells are set to 0.

21model.py: the network

Encoding the board into planes

battleship/dqn/model.py

planes = [grid == HIT, grid == MISS, grid == SUNK, torch.ones_like(grid)]   # 4 planes of 0/1
planes.append(remaining.view(n, 5, 1, 1).expand(n, 5, size, size))          # 5 "ships left" planes
if dens is not None:
    planes.append(dens.view(n, 1, size, size))                              # density plane (B, C)
return torch.cat(planes, 1)                                                 # shape: n × planes × 10 × 10

The network

for _ in range(net.layers):                                   # 4 times:
    layers += [nn.Conv2d(width, net.channels, 3, padding=1),  #   32 filters of 3×3
               nn.ReLU()]
self.body      = nn.Sequential(*layers)
self.advantage = nn.Conv2d(width, 1, 1)                       # A: one number per cell
self.value     = nn.Sequential(nn.Linear(2 * width, 64),      # V: from global pooling
                               nn.ReLU(), nn.Linear(64, 1))

padding=1 adds a ring of zeros around the board so each 3×3 filter also fits at the edges and the output stays 10×10.

The forward pass (computing Q)

h = self.body(x)                                           # 32 feature planes
a = self.advantage(h).flatten(1)                           # A(s, a): n × 100
v = self.value(torch.cat([h.mean((2, 3)), h.amax((2, 3))], 1))   # V(s): mean + max over the board
a_mean = (a * legal).sum(1) / legal.sum(1)                 # mean of A over legal cells
q = v + a - a_mean                                         # dueling: Q = V + A − mean A
if self.net.residual > 0:
    q = q + self.net.residual * dens                       # variant C: + c · density
return q.masked_fill(~legal, float("-inf"))                # fired cells can never be chosen

For variant C, nn.init.zeros_(self.advantage.weight) makes A start at zero, so the argmax is the density's argmax.

22train.py: the learning loop

The replay buffer

Fixed-size tensors on the GPU. New transitions overwrite the oldest ones (a circular buffer). We store the boards as small integers and rebuild the planes when sampling, which saves memory.

idx = (torch.arange(n) + self.pos) % self.capacity   # next n slots, wrapping around
store[idx] = value                                     # for board, action, done, next board, …

One iteration: act in 256 games

battleship/dqn/train.py

q = _q(online, board, remaining, dens, config)          # Q for all 256 boards
actions = q.argmax(1)                                    # best legal cell in each game
explore = torch.rand(env.n) < epsilon()                  # ε-greedy: which games explore
actions[explore] = torch.multinomial(legal[explore].float(), 1).squeeze(1)  # random legal cell
done = env.step(actions)
replay.add(board, remaining, dens, actions, done, next_board, next_remaining, next_dens)
env.reset(done)                                          # finished games start a new board

Then a few gradient steps

b, r, d, a, dn, nb, nr, nd = replay.sample(tc.batch)                 # random batch
q_sa = _q(online, b, r, d, config).gather(1, a[:, None]).squeeze(1)  # Q_θ(s)[a]
with torch.no_grad():                                                # targets: no learning here
    q_next_t = _q(target, nb, nr, nd, config)                        # target network θ⁻
    best = _q(online, nb, nr, nd, config).argmax(1, keepdim=True)    # Double DQN: online chooses
    q_next = q_next_t.gather(1, best).squeeze(1)                     #   target evaluates
    y = -1.0 + tc.gamma * torch.where(dn, 0, q_next)                 # y = −1 (+ γ·Q′ if not done)
loss = F.smooth_l1_loss(q_sa, y)                                     # Huber loss
opt.zero_grad(); loss.backward(); opt.step()                         # gradient descent
if grad_steps % tc.target_every == 0:
    target.load_state_dict(online.state_dict())                      # θ⁻ ← θ

Compare with the pseudocode in section 11: it's line for line the same algorithm.

  • .gather(1, a[:, None]) picks, from 100 Q-values per row, the one for the action actually taken.
  • torch.no_grad() means "don't compute slopes here". The target is treated as a fixed answer, not something to learn.
  • torch.where(dn, 0, q_next): if the game ended (done), there's no future, so the target is just −1.

Evaluation during training

Every 5,000 games, play_greedy plays the current network with ε = 0 on fixed validation boards (all 264 layouts on 4×4; 500 boards from seeds 100000+ on 10×10). The best-scoring checkpoint is saved as best.pt. The final benchmark uses different boards (seeds 0–1999), so picking the best checkpoint doesn't make the final score look better than it is.

23agent.py: playing a real game

The training code uses the fast tensor games. To be sure the agent plays the real game, under the same rules as every other agent, DQNAgent plugs into the project's normal engine (play_solo, evaluate):

battleship/dqn/agent.py

def select_shot(self, obs):                    # obs = the public observation only
    board = board_codes(obs).unsqueeze(0)      # CellState → 0/1/2/3, as a batch of 1
    remaining = remaining_counts(obs).unsqueeze(0)
    x, legal, dens = features(board, remaining, obs.config, self.model.net)
    return int(self.model(x, legal, dens)[0].argmax())   # best legal cell

It receives only the Observation (the public board), never the layout.

How to read a log line:

games  15002  eval  52.37 ± 0.86  train  53.47  eps 0.020  loss 0.355   124s
  • eval: mean shots on the validation boards with ε = 0, and its 95% margin. This is the number that matters.
  • train: mean shots of recent training games (includes ε's random shots).
  • loss: the Huber loss. It doesn't need to go to 0: targets are noisy because the hidden layout varies.

An interval that excludes 0 means the difference is real, not luck.

  • A learned from 90.5 to 52.4 validation shots within 15k games (about the best published DQN, ~52), then became unstable while its loss kept rising: the classic DQN divergence from section 9.
  • B shows that the density helps a lot as an input: 7.2 shots better than A, and only 1.2 behind the expert.
  • C started at the density level, but early corrections were badly calibrated and pushed it to 56 shots; it recovered to about 45 without beating its starting point.
  • Where the DQN loses shots: it hunts in fewer shots than density (17.1 against 27.5), but fires many more while a damaged ship is still afloat (28.8 against 17.2). It tends to leave a hit ship and probe elsewhere before finishing it.
What this means A network learns Battleship from experience far more efficiently than a table does, but with one seed and untuned settings it doesn't beat the hand-written expert. Full analysis: docs/design_dqn.md and report/dqn_report.pdf.
